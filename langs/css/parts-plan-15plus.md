## 6. Инструкции по созданию отдельного `css-guide-partN.md`

### 6.1 Имя файла и расположение
- `css-guide-partN.md`, без пробелов, номер без ведущих нулей — как во всех существующих 15 файлах.
- Один файл = одна часть.

### 6.2 Шапка файла
Актуальный формат (наблюдается в part12–15):
```
# CSS GUIDE — PART N
## Chapters X–Y

---
```
**Важно:** диапазон `X–Y` фиксируется **после** того, как часть реально дописана, и должен точно совпадать с фактически написанными главами (см. раздел 0.2 — во всех 4 последних частях шапка была неточной). Если диапазон указывается заранее как план — помечайте его явно как «(план)», чтобы не повторять путаницу.

### 6.3 Формат главы
- `## <номер>. <НАЗВАНИЕ ЗАГЛАВНЫМИ>`
- Сразу за заголовком — один блок ```css. Это стабильный паттерн начиная с главы 117 и далее.
- Формат `### <номер>.<под-номер> Под-название` с отдельным блоком кода на каждую подтему использовался только в главах 1–116, и только когда заголовок реально объединял 2+ разных по сути компонента (пример: гл. 106 Media Player → 106.1 Audio, 106.2 Video). Для новых глав 211+ такой формат уместен, только если тема прямо это требует (например, гл. 218 может логично делиться на checkbox/radio vs range/progress, если объём того потребует).
- Внутри одного ```css блока разные состояния/варианты разделяются инлайн-комментариями вида `/* ─── Label ─── */`, а не markdown-заголовками.
- Классы — BEM-подобные: `.block`, `.block__element`, `.block--modifier`, `.block.state-class`.
- Обязательно переиспользовать уже существующие design-токены из главы 2.3 (`--space-*`, `--color-*`, `--radius-*`, `--shadow-*`, `--font-*`, `--duration-*`, `--letter-spacing-*` и т.д.) — не вводить новые имена токенов без необходимости.
- Главы разделяются строкой `---`.

### 6.4 Язык
- База и part2 — русский; part3 и все последующие — английский.
- Для частей 16–20 — придерживаться английского, для консистентности с последними ~150 главами.

### 6.5 Закрывающий баннер части
Формат (пример из part15):
```
╔══════════════════════════════════════════════════════════════════════╗
║                     PART N — COMPLETE                                ║
║  Chapters X–Y | K new chapters | Output: css-guide-partN.md          ║
╚══════════════════════════════════════════════════════════════════════╝
```
- `K` и диапазон `X–Y` должны быть реальными — это единственное место, где во всех 15 частях данные оказались точными; сохраняйте эту точность.
- Не использовать формулировки «guide complete / final / the end of the guide» ни в одной части, кроме настоящей part 20 — такая формулировка уже 4 раза оказывалась ошибочной (см. раздел 0.3).

### 6.6 Чек-лист перед началом новой части
1. Проверить последнюю реально написанную главу предыдущей части (по её закрывающему баннеру, не по шапке) — новая часть стартует со следующего номера.
2. Сверить тему с полным списком уже использованных заголовков (1–210, плюс всё, что уже добавлено из этого плана) — не дублировать.
3. Не заявлять в шапке диапазон шире, чем реально планируется закрыть за один проход.

### 6.7 Чек-лист после завершения части
1. Пересчитать реально написанные главы и поправить шапку файла под факт.
2. Обновить закрывающий баннер (диапазон + количество).
3. Если это не part 20 — писать только «PART N — COMPLETE» (часть завершена), не «guide complete».
