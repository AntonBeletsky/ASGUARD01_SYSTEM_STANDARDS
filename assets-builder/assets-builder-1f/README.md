# assets-builder — два способа получить один и тот же результат

Задача одна: собрать разбросанные по папкам CSS/JS файлы front-end проекта в два документированных файла (`style.css`, `scripts.js`) с разбором зависимостей, домино-анализом и обнаружением конфликтов — чтобы шаблон можно было продавать. Решена она **дважды, но не двумя разными инструментами, а двумя разными интерфейсами к одному и тому же инструменту**.

```
assets-builder-complete/
├── README.md                       ← вы здесь
├── 1-script/                       способ 1: запускаете сами, из командной строки
│   ├── assets-builder.py           ← сам инструмент, один файл
│   ├── example-project/            рабочий пример: исходники + уже собранный dist/
│   └── docs/
│       ├── TZ-assets-builder-script.md          что должно быть (включая startgui/help)
│       └── ACCEPTANCE-REPORT-script.md          что реально подтверждено тестами
└── 2-skill/                        способ 2: устанавливаете в Claude
    ├── assets-builder.skill        ← готовый к загрузке архив (это zip; внутри —
    │                                  SKILL.md, references/, тот же assets-builder.py)
    └── docs/
        ├── TZ-assets-builder-skill.md
        └── ACCEPTANCE-REPORT-skill.md
```

`assets-builder.py` внутри `2-skill/assets-builder.skill` — **буквально тот же файл**, что и `1-script/assets-builder.py` (проверено сквозным тестом: `build` с одинаковыми параметрами через прямой CLI и через `startgui` даёт побайтово идентичный результат — см. `docs/ACCEPTANCE-REPORT-script.md`, критерий 4 в разделе 7). Скил не переизобретает логику — он оборачивает готовый скрипт и добавляет слой суждения там, где чистая автоматика сознательно останавливается и передаёт решение человеку.

Никаких отдельных «планов реализации» в этом наборе больше нет — это были трекеры исполнения задач, актуальные только пока работа шла; всё, что в них подтвердилось, перенесено в ТЗ (что построено) и в отчёт о приёмке (что проверено), а сами трекеры удалены как отработавшие своё.

## Чем способы отличаются на практике

| | 1-script (скрипт) | 2-skill (скил для Claude) |
|---|---|---|
| Кто запускает | Вы сами, из терминала | Claude — вы просто описываете задачу словами |
| Что нужно знать | Флаги CLI, либо меню `startgui` (то же самое, цифрами) | Ничего, кроме что вы хотите |
| Что происходит при конфликте (`severity: high`) | Флаг `--on-conflict warn/fail` решает заранее | Claude останавливается и спрашивает именно про этот конфликт, объяснив последствия |
| Где хорошо | CI/CD, регулярная пересборка, полный контроль | Разовая подготовка шаблона, не хочется разбираться в флагах |
| Что получаете | `style.css` + `scripts.js` + отчёты | То же самое + разговор о том, что найдено и почему |

Если сомневаетесь — начните со способа 2 (скил): он ниже по порогу входа и по ходу покажет вам реальный CLI-вызов, который использовал, так что при желании вы в любой момент сможете перейти на прямой запуск скрипта.

## Способ 1 — `1-script/`

```bash
pip install beautifulsoup4 tinycss2 --break-system-packages
python assets-builder.py build --project ./my-template --mode extended

# не хочется помнить флаги — то же самое через меню:
python assets-builder.py startgui

# что вообще умеет инструмент:
python assets-builder.py help
```

`example-project/` — можно открыть `example-project/dist/style.css` и сразу увидеть формат комментариев, не запуская ничего.

## Способ 2 — `2-skill/`

`assets-builder.skill` — обычный zip с папкой `assets-builder/` внутри (SKILL.md, `references/*.md`, `scripts/assets-builder.py`). Если хочется посмотреть содержимое без установки — распакуйте его как любой архив.

**Как установить** (Claude.ai — веб/десктоп/мобильный, актуально на момент подготовки, интерфейс может измениться):
1. В настройках убедитесь, что включено «Code execution and file creation» (Settings → Capabilities для личного аккаунта; для Team/Enterprise — Organization settings → Skills).
2. Customize → Skills → «+» → «Create skill».
3. Загрузите `assets-builder.skill`.
4. Включите тумблер — загруженные скилы по умолчанию выключены.

Для Claude Code вместо загрузки распакуйте `assets-builder.skill` в `~/.claude/skills/` (лично для себя) или `.claude/skills/` внутри репозитория (на проект) — там уже будет готовая папка `assets-builder/`.

После установки достаточно попросить словами: «собери мне все стили и скрипты из этого проекта в один файл для продажи» — остальное по `SKILL.md` внутри архива.

## Если нужны детали устройства, а не только результат

`docs/` в каждой папке — ТЗ (что построено, включая расширение `startgui`/`help` и обоснование каждого нетривиального решения) и отчёт о приёмке (что реально проверено тестами: все критерии из ТЗ, плюс найденные и исправленные по ходу баги — включая самозагрязнение через `dist/`, потерянную при правке строку кода и смешанный англо-русский текст, который проскочил в первой версии английского режима). Читать эти документы не обязательно, чтобы просто воспользоваться инструментом — но это единственный источник, где решения объяснены, а не только продекларированы.
