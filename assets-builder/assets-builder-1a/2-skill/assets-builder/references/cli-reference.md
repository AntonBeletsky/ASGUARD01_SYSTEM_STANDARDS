# CLI-справочник `assets-builder.py`

Основано на фактически реализованном и провалидированном коде (`scripts/assets-builder.py`), а не на изначальном ТЗ — там, где реализация отличается от ТЗ, отмечено явно.

## Подкоманды

| Команда | Назначение | Пишет файлы? |
|---|---|---|
| `scan` | Анализ + отчёт, без записи `style.css`/`scripts.js` | Только отчёт (если указан `--report`/`--report-json`) |
| `build` | Полный пайплайн: анализ + сборка + отчёт + (если не `--no-cache`) кеш | Да |
| `impact <file>` | Домино-анализ для одного файла: какие страницы затронет его изменение | Нет |
| `clean-cache` | Удалить файл кеша | Удаляет 1 файл |

## Общие флаги (все команды, кроме `clean-cache`)

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--project <path>` | обязателен | Корень проекта |
| `--exclude <a,b,...>` | `""` | Доп. паттерны исключения (через запятую, fnmatch-синтаксис). Всегда ДОПОЛНЯЮТ, не заменяют `DEFAULT_EXCLUDE = ["dist/**", ".git/**", "node_modules/**"]` |
| `--vendor <a,b,...>` | `""` | Доп. явные vendor-паттерны. Эвристика (`*.min.css`, `*.min.js`, папки `vendor/`,`lib/`,`libs/`,`plugins/`,`node_modules/`) работает всегда, вне зависимости от этого флага |
| `--cache <path>` | `.assets-builder-cache.json` | Путь кеша, относительно `--project` |
| `--no-cache` | выкл. | Не читать и не писать кеш |
| `--mode` | `basic` | `basic` \| `extended` (расширенный — с картой использования, медленнее) |
| `--quiet` | выкл. | Подавить консольный вывод (отчёты всё равно пишутся, если указаны пути) |
| `--verbose` | выкл. | **Пока no-op** — принимается, но не меняет поведение |

## `scan`

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--report <path>` | не пишется | Markdown-отчёт, если указан |
| `--report-json <path>` | не пишется | JSON-отчёт, если указан |

**Код возврата**: `0` — high-severity конфликтов не найдено; `1` — найден хотя бы один CSS- или JS-конфликт с `severity: "high"` (это сигнал, не ошибка выполнения).

## `build`

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--out-css <path>` | `dist/style.css` | Относительно `--project`, если не абсолютный |
| `--out-js <path>` | `dist/scripts.js` | Аналогично |
| `--report <path>` | `dist/build-report.md` | |
| `--report-json <path>` | `dist/build-report.json` | |
| `--on-conflict` | `warn` | `warn` (собрать, пометить комментариями) \| `fail` (прервать до записи файлов) |
| `--on-order-conflict` | `warn` | То же, но для противоречий порядка JS между страницами |
| `--strip-unused` | выкл. | Только `extended`-режим; удаляет CSS-правила со статусом `unused`. **Никогда** не трогает `dynamic-suspect` — гарантия на уровне кода, не только документации |
| `--comment-lang` | `en` | `en` \| `ru` — язык подписей в заголовках-комментариях (`FILE`/`ФАЙЛ` и т.д.) |

**Код возврата**: `0` — успех; `2` — `--on-conflict fail` и найден high-severity конфликт (файлы НЕ записаны); `3` — `--on-order-conflict fail` и найден `jsOrder`-конфликт (файлы НЕ записаны).

Если выходные пути (`--out-css`/`--out-js`) указаны вне `dist/`, скрипт всё равно исключит их точные пути из следующего анализа — но безопаснее оставлять дефолт.

## `impact <file>`

Позиционный аргумент `<file>` — путь **относительно `--project`**, ровно как он выглядит в отчётах (`assets/css/base.css`, не абсолютный и не с ведущим `/`). Код возврата `2`, если файла нет в индексе проекта.

## `clean-cache`

Только `--project` и `--cache`. Всегда код возврата `0` (даже если кеша не было).

## Отличия от исходного ТЗ (`TZ-assets-builder-script.md` §8)

- `--js-parser heuristic|ast` — реализован только `heuristic` (был дефолтом и там). Флаг `ast` в CLI отсутствует, не указывай его пользователю как рабочую опцию.
- Формат имени лога/уровня — `--quiet`/`--verbose` есть, но `--verbose` не расширяет вывод.
