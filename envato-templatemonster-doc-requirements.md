# Требования к документации для шаблонов сайтов (Envato / ThemeForest и TemplateMonster)

Собрано по официальным гайдам для авторов Envato и TemplateMonster, актуальным на сентябрь 2026 года. Применимо к HTML/CSS/JS-шаблонам, React/Vue/Angular-шаблонам, WordPress и другим CMS-темам — требования к самой документации почти везде одинаковые, отличия отмечены отдельно.

## 1. Зачем это вообще нужно

- Без документации товар не пройдёт модерацию ни на одной из площадок — это одно из первого, что проверяют.
- TemplateMonster прямо называет отсутствующую или слабую документацию одной из самых частых причин отправки товара на доработку.
- Хорошая документация снижает число обращений в поддержку и напрямую влияет на продажи — обе площадки называют её значимым фактором конверсии.

## 2. Общие требования (одинаковы для обеих площадок)

Обязательные разделы:
- **Установка** — пошагово, от распаковки архива до первого запуска (включая импорт демо-контента, если он есть).
- **Настройка/кастомизация** — как менять цвета, шрифты, секции; отдельно — настройка формы обратной связи, если она есть.
- **Структура файлов** — что лежит в каких папках, со скриншотами.
- **Требования к окружению** — версии CMS/PHP/Node/браузеров, если это критично для работы шаблона.
- **Кредиты сторонних ресурсов** — все шрифты, иконки, фото, плагины и библиотеки не вашего авторства, с указанием лицензии и ссылкой на источник.
- **Что не входит в архив** — стоковые фото для превью, платные шрифты/плагины, ключи активации: если чего-то нет в поставке, это нужно написать прямым текстом.
- **FAQ**.
- **Changelog** — история изменений с датами.
- **Контакты поддержки** и описание, что в неё входит.

Общие правила подачи:
- Язык — английский, это официальное требование обеих площадок.
- Пишите так, будто у читателя нет опыта в коде — разворачивайте объяснения, добавляйте скриншоты.
- Видео/скринкаст — только дополнение к тексту, никогда не замена.
- Обновляйте документацию вместе с каждым релизом, указывайте дату последнего обновления.
- Технология (голый HTML/CSS, React/Vue/Angular, WordPress, Shopify и т.д.) не меняет список разделов — только детали внутри них.

## 3. Главное отличие между площадками — формат файла

| Критерий | Envato / ThemeForest | TemplateMonster |
|---|---|---|
| Формат | PDF **или** HTML | Только **HTML** (PDF/TXT/XML — нежелательны) |
| Язык | Английский | Английский |
| Видео вместо текста | Нельзя, только дополнение | Нельзя, только дополнение |
| Одна документация на несколько товаров | Явно не запрещено | Явно запрещено — у каждого товара своя |
| Changelog | Хорошая практика | Обязательное поле формы загрузки, фиксированный формат |
| Папка в архиве | Обычно `documentation/` | `/Documentation` — фиксированное имя |

**Вывод**: если продаёте один и тот же товар на обеих площадках — делайте документацию сразу в HTML. Конвертировать HTML → PDF под Envato при необходимости проще, чем наоборот.

## 4. Envato (ThemeForest / Envato Market) — детали

### 4.1 Формат и содержание
PDF или HTML, на английском. Обязательно:
- краткие инструкции по установке, кастомизации и использованию;
- дополнительная общая информация;
- кредиты и ссылки на все сторонние ресурсы.

Envato публикует готовый скачиваемый шаблон файла документации в разделе для авторов — можно взять за основу.

### 4.2 Лицензии на ассеты
- Даже ассет, который используется только в превью и не входит в покупку, требует коммерческой лицензии.
- Если ассет физически включён в файл — нужна лицензия именно на **редистрибуцию** (право перепродажи), а не просто на использование.
- Если что-то не входит в поставку — это обязаны прямо указать и в описании товара, и в документации.

### 4.3 Папка Licensing (не для всех типов)
Нужна отдельная папка `/Licensing` с двумя txt-файлами внутри архива:
- Joomla, Drupal, OpenCart, osCommerce — лицензия GPL;
- Magento, PrestaShop — лицензия OSL v3.

Для **WordPress** папка не нужна — лицензия прикрепляется автоматически при загрузке.

### 4.4 Нюансы по типам шаблонов
- **Email-шаблоны** — документация должна учитывать вёрстку под почтовые клиенты (таблицы, инлайн CSS).
- **Figma / Adobe XD / Sketch** — важна ещё и организация самого файла (Pages/Frames, сетка), но письменная документация всё равно обязательна отдельно.
- **WordPress** — документация должна описывать импорт демо-контента и использованные сторонние плагины/библиотеки.

### 4.5 Что писать про поддержку (Item Support)
Если включаете платную поддержку — по политике Envato это минимум **6 месяцев** с даты покупки, можно продлить до 12. В поддержку входит: ответы на технические вопросы по функциям, помощь со сторонними ассетами товара, исправление багов. Не входит: установка «под ключ», кастомизация под конкретного покупателя, помощь с хостингом. Это разграничение стоит явно прописать в документации — снижает число спорных обращений.

*(На Envato Elements — подписочная модель — формальная Item Support policy не действует.)*

## 5. TemplateMonster — детали

Документация — в списке самых частых причин, по которым TemplateMonster отправляет товар на доработку, так что здесь особенно нет права на «и так сойдёт».

### 5.1 Формат
Только **HTML** — PDF/TXT/XML прямо не рекомендованы в гайде для авторов. Обязательна текстовая версия со скриншотами, видео — только как дополнение. У каждого товара своя уникальная документация, копипаст одного файла на разные шаблоны недопустим.

### 5.2 Обязательные разделы (must-haves)
1. **Installation Instructions** — пошагово, в идеале плюс видео.
2. **Server Requirements** — требования к хостингу/серверу/версиям ПО.
3. **Plugin Information** — какие плагины используются и как их подключать.
4. **Modification Guidelines** — как кастомизировать, со скриншотами, включая настройку формы обратной связи.
5. **Regular Updates** — документация обновляется вместе с продуктом, дата обновления актуальна.
6. **Complete information** — прямо указано, если нужны платные плагины/шрифты/ключи активации.

### 5.3 Чего в документации быть не должно
- ссылок на личные сайты, соцсети или другие маркетплейсы;
- одной документации «на все товары сразу»;
- расчёта только на видео/онлайн-формат без текстовой версии.

### 5.4 Где документация лежит в архиве

| Тип товара | Структура архива |
|---|---|
| CMS-темы (WordPress и т.п.) | `/Documentation` (HTML) + `/PSD` (опц.) + `/Demo Content` + `/themename.zip` |
| HTML-шаблоны | `/Documentation` (HTML) + `/PSD` (опц.) + `/themename.zip` |
| Графика | `/Documentation` (PDF/HTML) + `/Source Files` |

`readme.txt` в корне архива необязателен, но туда удобно вынести краткие credits и лицензионные детали.

### 5.5 Changelog — отдельное обязательное поле
Это поле в форме загрузки товара, а не файл внутри архива — но по сути тоже документация, пропускать нельзя.
- Формат даты: `MM DD, YYYY`.
- Категории записи: `Added`, `Changed`, `Deprecated`, `Removed`, `Fixed`, `Security`, `Updated`.
- Минимум около 30 символов на запись, иначе форма не даст сохранить.
- Публикуется в блоке Description после того, как модерация одобрит изменение.

Пример записи:
```
June 15, 2026:
- Fixed: mobile menu overlapping the hero section on small screens.
- Added: new "Pricing" page template with three plan layouts.
```

### 5.6 Что ещё пересекается с документацией при ревью
- Кросс-браузерная совместимость должна быть заявлена и в описании, и в документации.
- Любые сторонние плагины/модули обязаны быть описаны в документации, с гарантией совместимости от автора.
- За использование чужого ПО без лицензии отвечает автор товара.

## 6. Сводный чек-лист перед загрузкой

- [ ] Документация на английском
- [ ] Формат HTML (универсально для обеих площадок; PDF — доп. вариант только для Envato)
- [ ] Отдельная папка `Documentation` в архиве
- [ ] Пошаговая установка + скриншоты
- [ ] Раздел кастомизации/настройки
- [ ] Явно расписано, чего нет в комплекте
- [ ] Кредиты и лицензии на все сторонние ресурсы, со ссылками на источник
- [ ] Требования к серверу/CMS/версиям
- [ ] FAQ
- [ ] Changelog с датами (+ отдельное поле при загрузке на TemplateMonster)
- [ ] Контакты поддержки и описание, что в неё входит/не входит
- [ ] Для Joomla/Drupal/OpenCart/osCommerce/Magento/PrestaShop — папка `Licensing`
- [ ] Один товар = одна уникальная документация
- [ ] Указана дата последнего обновления документации
- [ ] Нет ссылок на личные сайты/соцсети/другие маркетплейсы (критично для TemplateMonster)

## 7. Рекомендуемая структура index.html документации

Годится как база под обе площадки:
1. Заголовок, версия шаблона, дата обновления
2. Оглавление
3. О шаблоне / с чего начать (Getting Started)
4. Требования (сервер, версии ПО, браузеры)
5. Установка
6. Настройка и кастомизация
7. Обзор структуры файлов
8. Сторонние ресурсы и кредиты
9. FAQ
10. История изменений (Changelog)
11. Поддержка — что входит, как связаться
