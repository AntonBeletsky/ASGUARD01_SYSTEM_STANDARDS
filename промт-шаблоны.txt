*** SOFTWARE DEVELOPMENT PROTOCOL: BILINGUAL CHECKLIST ***

1. CODE INTEGRITY (THE CORE)
---------------------------------------------------------------------------
[DRY]   NEVER DUPLICATE LOGIC. REDUNDANCY IS THE ENEMY OF STABILITY.
[KISS]  SIMPLICITY OVER COMPLEXITY. AVOID OVER-ENGINEERING.
[YAGNI] CODE ONLY WHAT IS MANDATED. NO GHOST FEATURES.
[NAME]  NOUNS FOR DATA, VERBS FOR ACTIONS. BE EXPLICIT.
[UNIT]  KEEP FUNCTIONS ATOMIC. ONE TASK PER SUBROUTINE.
[INFO]  CODE MUST BE READABLE. COMMENTS JUSTIFY INTENT, NOT SYNTAX.

2. SYSTEM ARCHITECTURE (SOLID)
---------------------------------------------------------------------------
[S] SINGLE RESPONSIBILITY: ONE MODULE, ONE REASON TO CHANGE.
[O] OPEN/CLOSED: EXTEND SYSTEM VIA NEW CODE, NOT MODIFICATION.
[L] LISKOV SUBSTITUTION: SUBTYPES MUST BE INTERCHANGEABLE.
[I] INTERFACE SEGREGATION: PREFER GRANULAR INPUTS OVER BULK OBJECTS.
[D] DEPENDENCY INVERSION: DEPEND ON ABSTRACTIONS, NOT HARDWARE/IMPLEMENTS.

3. LAYERED TOPOLOGY (CLEAN ARCHITECTURE)
---------------------------------------------------------------------------
[LAYER] CORE LOGIC (BUSINESS RULES) IS THE CENTER OF THE UNIVERSE.
[DIR]   DEPENDENCIES FLOW INWARD. KERNEL KNOWS NOTHING OF PERIPHERALS.
[DB/UI] HARDWARE INDEPENDENCE. DATABASE AND INTERFACE ARE PLUGINS.
[DTO]   CROSS BOUNDARIES USING DATA TRANSFER OBJECTS ONLY.

4. LOGIC PATTERNS (DESIGN SCHEMATICS)
---------------------------------------------------------------------------
[FACTORY]    DYNAMIC INSTANTIATION WITHOUT HARD-CODING TYPES.
[STRATEGY]   SWAPPABLE ALGORITHMS DURING RUNTIME.
[REPOSITORY] DATA PERSISTENCE IS HIDDEN BEHIND A CLEAN API.
[DECORATOR]  ADD WRAPPERS (LOGGING/CACHE) WITHOUT ALTERING SOURCE.
[OBSERVER]   EVENT-DRIVEN COMMUNICATION BETWEEN MODULES.

5. LOW-LEVEL STANDARDS
---------------------------------------------------------------------------
[TYPE]   STRICT TYPE HINTING. CONTRACTS MUST BE ENFORCED.
[LOGS]   SYSTEM LOGGING ONLY. "PRINT" IS FOR DEBUGGING, NOT PRODUCTION.
[EXCEPT] CUSTOM ERROR CLASSES FOR BUSINESS-SPECIFIC FAILURES.
[VALID]  VALIDATE ALL EXTERNAL INPUT AT THE SYSTEM FRONTIER.

6. RESILIENCE PROTOCOL (FAULT TOLERANCE)
---------------------------------------------------------------------------
[STATE]  STATE IS EXTERNALIZED. TRACK OFFSET, STATUS, AND CHECKSUMS.
[RESUME] AUTO-RECOVERY. RESUME FROM LAST CHECKPOINT AFTER POWER LOSS.
[ATOM]   ATOMIC I/O. WRITE TO TMP, THEN SWAP. NO CORRUPT FILES.
[IDEM]   IDEMPOTENCY. RE-RUNNING A TASK PRODUCES THE SAME RESULT.
[HEALTH] SELF-DIAGNOSIS ON BOOT. VERIFY INTEGRITY BEFORE EXECUTION.

*** END OF DOCUMENT ***
